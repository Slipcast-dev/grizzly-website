# Участие в разработке

[English](CONTRIBUTING.md) · **Русский**

Предложения и исправления приветствуются. Для обычных ошибок используйте issues, для уязвимостей — [SECURITY.ru.md](SECURITY.ru.md).

1. Создайте ветку или fork от `main`.
2. Внесите минимальное изменение. Сайт остаётся статическим, без добавления зависимостей без необходимости.
3. Синхронно обновляйте `index.html` и `en.html`, динамические сообщения и обе версии документации. Запустите команды из README.ru.md и проверьте обе страницы в узком и широком окне, клавиатурную навигацию, RU/EN, автовыбор языка и все три режима демонстрации (чтение, исходник и правка).
4. Откройте pull request: опишите проблему, результат и выполненные проверки. Для визуальных изменений приложите скриншот без личных данных.

Не добавляйте токены, `.env`, персональные данные, исполняемые установщики и файлы приложения. Установщики распространяются из релизов основного проекта. Не изменяйте permissions workflows без обоснования. Actions закрепляются полными SHA; не используйте `pull_request_target` для исполнения кода участников.

Перед слиянием должны пройти обязательные проверки и быть разрешены обсуждения. Вклад распространяется под лицензией MIT проекта. Соблюдайте [кодекс поведения](CODE_OF_CONDUCT.ru.md).

При изменениях вёрстки проверяйте обе локализации на ширинах от 320 px до компьютера, включая режим уменьшенного движения. Убедитесь, что горизонтального переполнения нет, главные кнопки одинакового размера, а подпись отцентрирована под ними. Для декоративных значков используйте inline SVG с `aria-hidden="true"` и `focusable="false"`, а не символы стрелок из шрифта.

Сохраняйте размер описаний возможностей 14 px, вспомогательных подписей — 11–12 px, с читаемым контрастом. Ссылки шапки должны находиться на одной линии; логотип GitHub и значки ссылок в подвале не должны превышать размер текста. Выравнивайте отступы карточек и нижние подписи, сохраняйте перенос вводного текста на телефоне и центрируйте мобильный подвал. Используйте список размеров экрана из [README](README.ru.md), просматривайте скриншоты в исходном масштабе.

После слияния PR и проверки опубликованного коммита удаляйте завершённую ветку. Перед удалением локальной ветки проверьте уникальные изменения; при squash-слиянии сравните содержимое с результатом слияния. Не удаляйте ветки открытых PR и неслитые изменения.
